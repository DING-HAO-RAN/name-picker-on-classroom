## 本轮改动（「双击图标报保存失败」排查与修复）

- 用户报：双击图标无法正常打开，弹「名单状态保存失败，请重试。」
- **排查过程**：
  1. 本机 userData 为 `%APPDATA%\name-picker\roster-state.json`（9-13 格式，目录可写）→ 排除权限/损坏。
  2. 本机复现曾大面积失真：**宿主会话带 ELECTRON_RUN_AS_NODE=1**，spawn 的 Electron 会以纯 Node 模式启动直接崩溃——复现必须从子进程 env 删除该变量。
  3. 沙箱 GPU 不可用，启动复现需带 --disable-gpu。
  4. release13 打包时与并行会话竞争，**win-unpacked 缺 32 个文件（含 icudtl.dat）**→ 启动报「Invalid file descriptor to ICU data」。换 release14 重打完整（73 文件）。
  5. **发现并行会话在同时改这个项目**（提交 6dc8984 修了锁时序、把重命名重试与 card 动画样式持久化入库；上一轮我的提交实际未入库——工作区改动由本轮 57e727b 统一提交）。
- **根因**：release12 中 `whenReady().then(初始化+createMainWindow)` **不受单实例锁保护**。第二实例 `app.quit()` 后 Electron 仍完成启动（ready 照常触发），导致第二实例创建窗口→加载存档→触发迁移保存→进程退出中写入失败→渲染器弹「保存失败」且窗口闪退。
- **修复**：`gotSingleInstanceLock` 前置，whenReady 移入拿锁成功的 else 分支——第二实例安静退出，旧实例 second-instance 唤起窗口。
- **验证**：tsc 0 错；vitest 179 全过；双开验证（release14）——第二实例秒退、第一实例状态「已保存」无失败 toast（曾一次误报系并行会话实例持有锁，属预期行为）。
- 打包：release13 损坏弃用，release14 完整交付（Setup 84.7MB + portable 84.5MB）。下轮输出目录 release15。
- 教训：**诊断 Electron 启动问题先查 ELECTRON_RUN_AS_NODE**；并行会话同时改同一项目时，打包前先 git status 确认代码归属。


## 修复「双击图标无法正常打开 + 名单状态保存失败」（commit `6dc8984`，release13）

- **根因 1（主因）**：单实例锁 `requestSingleInstanceLock()` 写在 `void app.whenReady().then(...)` **之后**。旧实例驻留后台时双击图标 → 新实例拿锁失败 `app.quit()`，但 ready 竞态下 whenReady 回调仍可能执行 → 创建窗口、读档、触发迁移保存——应用正在退出，写入失败 → 「名单状态保存失败」toast + 窗口闪退。**修复：锁检查移到文件最前，失败分支完全不注册 whenReady**。
- **根因 2**：Windows 上 rename 偶发 EPERM（目标被杀软/索引服务短暂锁定）。**修复：renameWithRetry 间隔 120ms 重试 3 次**。
- **附带 bug**：animationStyle 白名单漏了 'card'，选抽卡式后重启样式回退。已补。
- 过程插曲：构建期间 D 盘被 releaseN 产物塞满（ENOSPC，连工具临时文件都写不了）。清空回收站 + 删 release2-9 后恢复；release10 因用户取消删除而保留。**教训：每次打包的 releaseN 目录约 400MB，长期迭代必须及时清理旧目录；沙箱删除会走回收站，满盘时清回收站才能真释放。**
- 验证：tsc 0 错；vitest 179 全通过；打包 release13（Setup 84.7MB + portable 84.5MB）。下轮输出目录 release14。
